# Font builder

*Scripts > FreeLab > Font Builder* makes template sheets to draw a font's glyphs on, in any app or on paper, and builds the glyphs from the sheets drawn: traced into outlines, or kept as images. The other tools then take over: *Auto Spacing* spaces them, *Glyph Compose* builds the accented letters and the rest from them, *Feature Code* writes their features.

The window is laid out as every FreeLab window ([WINDOWS.md](WINDOWS.md#layout)); the font's metrics shape the template's boxes. While the *Template* tab is shown, the template's status stands under the top line (how many glyphs on how many sheets, or *No glyph to draw*), and the tabs' frames line up with the log's (image 268). With no font open, the top line is one line: *No font is open. This window hooks to the next font you open (or build here). A template can still be made, with default metrics.* (images 274 and 280). Each tab's options stand on one line with their run button at the end (*Save template…*, *Read sheets*: images 241, 266, and 267), and wrap onto the next line, in their order, where the window is too narrow (`FlowRow`). *Build ticked glyphs* stands in the window's bottom row, at the right before *Cancel* and *Close*, while the *Build* tab is shown (*Cancel* is usable while a save or a read runs: [WINDOWS.md](WINDOWS.md#long-work)); a tab switch hides the other tab's buttons before it shows this one's (`ak.show_only`), so the row never holds both and the window keeps its width. The row above each tab's frame (*Character set:* and its dropdown, then *Text size:*; *Add sheets…* and *Clear*) is as tall as the other's, so the frames never shift as the tabs switch (images 285 and 286).

## Template

- **Character set** (captioned as Glyph Compose's dropdown of the same sets): the characters typed or pasted in the box (each once; spaces do not count), or one of Font Check's character sets (its scripts, Unicode blocks, and foundries' sets). The common sets come first (Latin, Cyrillic, Greek, Arabic, Hebrew, Devanagari, Thai, kana, the main Chinese, Japanese, and Korean sets, punctuation, currency), then a line, then every set, the common ones again among them. The line has 4 pixels of room above and below it in the open list, so the two groups read apart: a delegate of FreeLab's stands in front of Qt's own on the list, asks it for every row's size and painting, and makes only the separator's row taller (`separator_room`; a stylesheet cannot set that height, and dark mode leaves the list as drawn). A set picked fills the box with its characters, to edit: once edited, the choice is *Characters typed below*. The set picked is kept at once in *font_builder.json*, by Font Check's code for it (*script:Yi*, *unihan-big5*), which stays when the sets are made again, where a row's place and a label's count of characters do not; the window reopens on that set, its characters in the box. Characters typed or edited by hand (they differ from the set's) come back as *Characters typed below*, and so do the characters of a set that is no longer there. A list too long for its screen scrolls, with a scroll bar (every FreeLab dropdown does).
- **Text size** (right of the dropdown; 12 points by default, 6 to 72): the size of the characters in the box below, kept from one session to the next in *font_builder.json*. It changes only what the box shows, never the sheets, whose size is the *Em size*.
- **The box** shows its characters in *FreeLang*, the font Font Check's and Glyph Compose's lists use, through Font Check's own `register_list_font`: the first file, with the four optional ones as its substitutes, so every set the dropdown offers is drawn wherever FreeLang has its characters (in the window's font, Yi's 1,220 characters were boxes). FreeLang is registered the first time the box holds a character past ASCII (a set picked, or text typed or pasted), not as the window opens, and once a session. When a set picked needs optional fonts that are not installed (a copy that lacks them), one line under the box names them and says to install FreeLab again to get them ([INSTALL.md](INSTALL.md#freelang)); the line goes once the box holds ASCII alone. Which fonts a set needs is Font Check's judgment (`fallbacks_needed`, `names_characters`), and the Duployan font for the Duployan sets, which it alone draws.
- **Leave out the glyphs the font has drawn** (ticked to start with; with a font open, grayed out without one): no box for a glyph that has outlines, components, or an image in the current master.
- **Print each character faintly as a guide.** (ticked at first, kept in *font_builder.json*): each box's character printed very faintly in FreeLang, to show what to draw ([Guide characters](#guide-characters)). Unticked, the sheets are as they were before the option: the same painting, and the same SVG text but for the marks' group of their own (below).
- **Alternates of each**: boxes for *name.alt1*, *name.alt2*, and so on after each glyph, for a handwriting font's alternates (Feature Code makes them take turns).
- **Glyphs per sheet** (100 by default, 400 at most): there are as many sheets as the glyphs need. A sheet larger than 120 megapixels gets fewer, so a CJK set at a large em size makes more, smaller sheets.
- **Em size** (500 pixels by default, from 150 to 1,200, kept in *font_builder.json*): the em on the sheet. 500 draws well on a screen; for print at 300 dpi, an em of 500 pixels is 4.2 cm. The font never changes it, nor its default: an em is that many pixels whatever the font's units per em. The font's metrics set where the lines fall within the em and how tall a box is (below).

A glyph is named as the font names it, where it has the character; else by its usual name (the Adobe Glyph List's for ASCII, Glyphs' for the rest, from Glyph Compose's *glyph_names.json*); else *uniXXXX*.

Each glyph has a box: its em with the font's ascender, cap height, x-height, baseline (thicker), and descender, and an origin line, room above and below for accents and swashes, and the character over it with its glyph name. A box is 1.2 em wide, its origin line 0.1 em from its left side; it is as tall as the font's ascender to its descender, plus 0.15 em above and below, each line at its value in the font's units times *Em size* over the units per em. They are drawn in a pale blue (a gray of about 205) that the reading leaves out, over the box's character printed fainter still, as a guide ([Guide characters](#guide-characters)). Without a font open, the metrics are 1000 units to the em, ascender 750, descender −250, x-height 500, cap height 700.

*Save template…* writes one SVG drawing a sheet, numbered (*Family-1-of-3.svg*), the type its dialog starts with (*SVG drawings (vector)*, image 374): the same sheet as the image, its pixels the drawing's units, for vector apps (Illustrator, Inkscape, Affinity Designer) and any app that opens SVG. The paper, the boxes, their lines and labels, and the guide characters are a locked group (*template*); the corner squares and the bands, a locked group of their own above it (*marks*); and an empty group (*drawing*) above both is there to draw in. The marks are drawn last, as they always were, so the drawing renders as before. Its dialog also writes one file a sheet in three other formats, listed in this order after SVG (each type names a kind of file in the plural, as Windows' own lists do; Qt reads a type's last parentheses as its patterns, so *(vector)* and *(layered)* stay words of the name, and the extension of the name chosen decides the format):

- **PNG** (*PNG images*): a flat image.
- **TIFF** (*TIFF images*): a flat image, LZW-compressed (lossless). Qt's plain save wrote TIFF uncompressed: measured live in FontLab's Qt 5.14, a sheet of 7,518 by 9,996 pixels took 220 MB, 1.6 MB with LZW (0.8 MB as PNG).
- **PSD** (*Photoshop documents (layered)*): three layers, bottom to top: *Marks (keep visible)*, the corner squares and the bands on white, locked; *Template (can be hidden)*, the boxes, lines, labels, title, and guide characters on a clear ground, locked; and *Draw here*, empty, to draw on. *Template (can be hidden)* prints in strong colors at 33% opacity (85 of 255), so it looks as the flat sheet does, and raising its opacity makes the boxes, labels, and guides stand out: each color is stored three times as far from white as painted (255 − (255 − c) × 255 ⁄ 85), the lines and labels at 0, 135, 240 (painted 170, 215, 250, the template's darkest, so nothing is clipped) and the guide characters at 153, 207, 249 (painted 221, 239, 253); at 85, every stored value is whole, and the layer over white gives the sheet back exactly (*tests/font_builder_tests.py* composites the layers and compares). Its name says what is true: it may be hidden before the sheet is saved, and need not be. The flattened picture that follows them is the whole sheet, so an app that reads no layers (FontLab's Qt among them) shows it as the PNG. FreeLab writes the file itself (Qt 5.14 writes no PSD, and FontLab's Python has no Pillow): Adobe's format, version 1, RGB at 8 bits, every channel PackBits-compressed, the layers' names as Pascal strings and as Unicode, their locks as Photoshop's three (transparency, pixels, and position). The lock is advisory in some apps: an app that knows no PSD locks lets the layers be painted on, so draw on *Draw here*. PackBits codes each row of pixels on its own, a blank one too (108 bytes a channel for a row 6,867 pixels wide), and the file holds the sheet three times (flattened, *Template*, and *Marks*), so a PSD is far larger than a PNG: measured on a sheet of 100 boxes at an em of 500 pixels (6,867 by 8,841 pixels, synthetic guide characters, two rings a box, no row repeated from another band), 20.1 MB, written in 2.9 s in Python 3 and 4.0 s in Python 2.7 (FontLab's), after Qt has painted the sheet. The bar moves as the rows are written, and *Cancel* or *Esc* stops between two bands of 256 rows.

In an SVG or a PSD, the boxes and guides may be hidden before a sheet is saved again: the reading needs only the marks, which must stay visible (a sheet with *Template (can be hidden)* hidden reads box for box as with it shown, *tests/font_builder_tests.py*).

The dialog does not ask before replacing a file itself (Windows' *Confirm Save As* box stays light in dark mode): FreeLab asks once, before anything is written, in its own box, for every file the save would replace, the name typed and the numbered sheets alike (*DotTest.tif already exists. Replace it with a new sheet?*; for several, *A.tif, B.tif, and C.tif already exist. Replace them with new sheets?*, a long list named in part: the first five, then *and 126 more*). Where FontLab's PythonQt cannot tell the dialog not to ask (`ak.save_file_name` tries it, then falls back on the plain call), Windows' box asks of the name typed as before, and FreeLab asks of the others only.

A save is all or nothing. Each sheet is written whole to a staged file beside its own (*Hand-1-of-3.k2x9_q4m.part.svg*), and the staged files take their places only once every sheet is written. A save stopped (*Cancel* in the question; *Cancel*, *Esc*, *Close*, the tools menu, or an arrow while it writes) or failed (a sheet that cannot be written) removes every staged file, replaces nothing, and leaves no new file; the log says *The operation was interrupted. Nothing was saved or overwritten.*, or names the sheet that could not be written. The staged files sit beside the final ones until the end, so a save needs room for all its sheets even where it replaces as many. Should a staged sheet fail to take its place at the very end (a file locked by another app), the moves stop there, and the log names the sheets saved and those not (their files there left as they were); the staged files are removed. A save also removes the staged files an earlier save of the same sheets left behind (FontLab ended while it wrote), matching only their own names, never another file.

As it starts, after the question, a save that will take 50 MB or more says so, from the sheets' layout, before anything is written; past 1 GB the line is a warning that names a lighter format, and the save goes on (81 sheets of 100 boxes at an em of 500 pixels, with guides: *Writing 81 sheets as PSD: about 1.5 GB. PNG and TIFF sheets of this template would take about 61.9 MB and 123.9 MB.*). A PSD is weighed by PackBits' own costs: each row's white, the marks' rows, and 9.5 bytes a box's row on each of the 7 channels that hold the template, 6 more for a guide character; on synthetic sheets of 4 to 25 boxes at ems of 60 to 300 pixels the estimate came within 5% of the writer's output (*EstimateTests*), and within 5% on a full sheet of 100 boxes at an em of 500 pixels (18.7 MB written); a guide of many strokes (a CJK character) weighs more than the model's. PNG and TIFF are weighed roughly, from live measures in FontLab's Qt (about 2.9 kB a megapixel, then each box and guide; TIFF twice PNG); SVG by its marks and boxes (within 20% of the text written), and 1.7 kB a guide. The log then says how many sheets were saved, their size together (*Saved 81 sheets (1.5 GB) in …*: KB under 1 MB, MB with one decimal under 1 GB, GB past it, counted by 1,024 as Explorer counts them), and where: the folder is a link that opens it in a new Explorer window with the first sheet selected (the Finder on macOS; image 375).

### Guide characters

With *Print each character faintly as a guide.* ticked, each box holds its character, printed very faintly in FreeLang (the font of the box above, through Font Check's `register_list_font`, registered at the save if the box has not registered it yet), in a lighter tint of the guides' pale blue (221, 239, 253: a gray of 235). It is drawn first, the box's lines over it.

- **Where it stands**: on the box's baseline, its em the sheet's *Em size*, so its capitals, x-height, ascenders, and descenders stand against the box's lines as a glyph drawn at that size would. FreeLang's heights are its own, not those of the font that shapes the box: the guide is placed by the baseline and the em, never stretched to the font's lines. Across, its origin stands on the box's origin line, FreeLang's sidebearings kept, which is how *Where drawn* reads a glyph; where its ink would then cross a side of the box (a wide glyph, a mark drawn left of its origin), its ink is centered in the box instead. A character taller than its box (a capital with two accents in a font of short ascenders) is cut to the box.
- **Which file draws it**: the first of FreeLang's files that has the character itself (FreeLang Essential, then whichever of the optional *FreeLang CJK*, *FreeLang+ General*, *FreeLang+ Mongolian–Tibetan*, and *FreeLang+ Duployan* are installed), asked of each file's own font (`QRawFont.supportsCharacter`, as Glyph Compose's lists ask), never of Qt's fallback. Qt shapes it alone: an Arabic or Hebrew letter in its isolated form, a mark as FreeLang draws it alone (on a dotted circle only where FreeLang's own shaping puts one).
- **What gets none**: a character none of the installed files draws (never a box: the line under the box names the optional files a set needs), a glyph with no character of its own (an alternate, *a.alt1*; a ligature's name), a character with no ink, and one wider than its box (a three-em dash). With no FreeLang at all, the sheets are saved without guides and the log says so: *No character was printed as a guide: FreeLang, FreeLab's own font, could not be loaded.*
- **In each format**: an image sheet (PNG, TIFF, and PSD, on its *Template* layer) is painted by Qt with the font itself, smoothed (its soft edges lighter than 235, never darker). An SVG sheet holds each guide as an outline in the locked *template* group (`<g id="guides">`, under the lines), so no app needs FreeLang to show it: path data to a tenth of a pixel, relative to the point before. Measured on Big Five in FreeLang CJK at an em of 500 pixels (FreeLang's outlines read with fontTools, as Qt gives them: 186 path elements a character), a guide takes 1.7 kB (2.8 kB in absolute coordinates), so a sheet of 100 boxes grows from 99 kB to about 271 kB, and Big Five's 13,064 boxes add about 22 MB over its 131 sheets; writing the path data takes 0.15 ms a character in Python, before PythonQt's own calls for each path element. A PNG sheet of 100 Big Five boxes grows from 0.2 MB to 0.8 MB. The guides are made under the window's bar, box by box, so *Cancel* or *Esc* stops between two boxes.

**Why the reading never takes it for ink.** The reading counts as ink only what is darker than *Ink darker than* (at most 185), on each box read upright from the image, after making that box's paper white ([Build](#build)). The guide is printed at 235 of white: 50 grays above the highest threshold, and 30 above the box's own lines (205), which the reading has always left out, so whatever leaves the lines out leaves the guide out with room to spare. Measured on synthetic sheets (*tests/font_builder_tests.py*, `GuideReadingTests`), an untouched sheet with guides reads as no ink in any box, at the default threshold and at 185: from the screen, after a simulated flatbed scan (the tint printed 15 grays darker, paper at 93%, a scanner's black at 24, a tone curve of 1.2, light falling off 3% across a box, noise, blur), after a phone photograph (paper at 80%, black at 40, a 5% fall-off), and from a scanner's 1 bit. The darkest guide pixel then reads 206 to 210 against its paper, 21 grays above 185. In *Images (as drawn)*, nothing of it is kept. Strokes drawn over a guide read as the same strokes drawn on a sheet without one, but at their smoothed edges: a pixel partly inked over the guide is a little darker than over white paper, so an edge moves by one pixel where its coverage was within a few hundredths of the threshold (of the edge pixels, 3% to 5% from a screen's sheet, 6% to 18% after a scan or a photograph, 19% from a scanner's 1 bit; never inside a stroke), and the traced outlines have the same contours, their extents within a hundredth of the em.

What it survives: the guide reads as ink only once its gray, against its box's paper, falls under the threshold. That takes a tone curve (gamma) of 8.4 on it at the default threshold, 3.9 at 185, or the light falling off by 46% (21% at 185) between a box's brightest paper and the guide. The box's lines fail first, at 3.2 and 1.5, and at 38% and 10%. Past that point the guide is traced as ink, as the lines are: lower *Ink darker than*. A box whose paper reads no lighter than the threshold (a photograph too dark for it) is read as it comes, all ink: lower the threshold until the paper reads lighter.

## Drawing

Open a sheet in any app (Photoshop, Clip Studio Paint, Krita, Procreate, Illustrator, Inkscape) or print it. Draw each glyph in dark ink inside its box, on the image or on a layer above it, and save or export each sheet again: PNG, JPEG, TIFF, BMP, WebP, PSD, or SVG. FontLab reads a PSD by the flattened picture the app saves with it, whatever its layers (none are read one by one): Photoshop saves a real one only with *Maximize Compatibility* (its *File Handling* preferences), and without it the sheet's row says *not read: a PSD without a flattened picture FontLab can read; save it in Photoshop with Maximize Compatibility, or as PNG* (Photoshop's *Version Info* resource says so; the same words where Qt reads no picture from a PSD at all). An SVG sheet is drawn by FontLab's Qt on white (its QtSvg renderer, else its SVG image plugin), at the size its `viewBox` gives (the template's own pixels, whatever units the app saved it in; 120 megapixels at the most), then traced as any image: filled shapes and strokes alike, so a vector app needs no *Outline Stroke*. Where FontLab's Qt can draw no SVG, the sheet's row says so and asks for a PNG. Transparent parts of any sheet read as white paper (a drawing exported from a clear layer). Paper can be scanned or photographed; a scanner's PDF is not read (FontLab 7's Qt reads no PDF): save its pages as PNG or JPEG.

The four corner squares and the two bands of black and white squares, over and under the boxes, tell the reading where the sheet is in the image and what it holds: its layout, its glyph names, and the metrics it was made with. A sheet needs no file beside it and no metadata (apps often drop it), so it can be read on another computer than the one that made it, and it can be turned, skewed, or photographed at a slant. Keep the squares and the bands clean and wholly in the image; one band is enough, so a smudge on one does no harm.

## Build

*Add sheets…* adds the sheets drawn, one file or several, in any order (PythonQt gives the files picked as a tuple of strings, not as PyQt's pair of the files and the filter); *Read sheets* finds each in its image, reads its layout from a band, and takes every box that holds ink:

- **Outlines (traced)**: each drawing traced into contours (FreeLab's tracer, after potrace's method: smooth curves, corners where the drawing turns sharply, nodes at extremes), specks and pinholes smaller than a square of 2% of the em dropped.
- **Images (as drawn)**: each drawing kept as an image in its glyph, cropped to its ink: black ink on a clear ground, its paper made white as for tracing, opaque up to half the ink threshold and clear from halfway between it and white, so the guides and the paper drop out and the ink keeps its soft edges. For a bitmap or color font, or to trace by hand.

**Ink darker than** (128 by default, 185 at most) is what counts as ink: raise it for pencil or light ink, lower it for gray paper. The guides are a gray of 205 once the image is gray, and the guide characters 235, so they stay out at any setting on a sheet as saved; a scan or a photograph whose paper is darker or more uneven than the reading can make white brings them closer, and the higher the setting, the sooner the lines, then the guide characters, show in the glyphs. Its tooltip and its help say so, with those numbers taken from the code's own constants: raise it only as far as pale ink needs, and lower it if lines appear. Each box's paper is measured first (where the brightest tenth of its pixels begins, `paper_level`) and made white (each gray times 255 over it, `paper_table`), so a scan or a photograph whose paper reads darker than white, or darker on one side of the sheet than the other, is read as a sheet drawn on a screen: before, a photograph whose paper read 150 had its guides' lines (then 120) traced as ink at the default threshold. A box whose paper reads white is read as before, byte for byte, and so is one whose paper reads no lighter than the threshold. **Glyphs placed**: *Where drawn* keeps the ink where it was drawn against the box's origin line and gives the right side the left side's room; *With even sidebearings* sets both sides to 5% of the em. *Auto Spacing* spaces them better either way.

The list shows each glyph as traced, the sheet it came from, and a note (its contours; the glyph it goes into, where the font names it otherwise; a glyph drawn on two sheets; one the font has drawn already). *Build ticked glyphs* writes the ticked ones into the current master as one step of FontLab's History (*Edit > Undo* takes it back):

- Each drawing goes into the font's glyph for its cell's character, whatever either is named: a sheet made from a font that calls A *A* fills this font's *uni0041*. Where the font has no glyph for the character, it goes into a glyph of the sheet's name, unless that glyph is for another character (a source font's *B* for A, where this font's *B* is U+0042): then into *uniXXXX*, or nowhere if that too is another character's (the log says so). A glyph added, or one of the font with no code point, takes the character's code point; none for alternates and ligatures, and none where another glyph of the font has it (the log names those).
- A glyph drawn more than once among the ticked rows (on two sheets, or under two names for one character) is built once, from the first; the log names the others.
- A glyph the font has drawn in the current master is left as it is unless *Replace glyphs the font has drawn* is ticked, also when it was drawn after the sheets were read.
- The lists stand for the font and master they were read for: after a switch to another master, *Build ticked glyphs* asks to read the sheets again.
- The ink is scaled from the units of the font the template was made with to this font's (a sheet made at 1000 units to the em, built in a font of 2048, keeps its size in ems).
- The outlines turn the font's way (TrueType or PostScript, read from its glyphs), and each drawing is made before its glyph is touched.
- With no font open (when the sheets were read and when building), *Build ticked glyphs* makes a new font first, open in its own window, and the window hooks to it at once (while FontLab shows it, as it does a font just made: `hook_built_font`): the units per em, ascender, descender, x-height, cap height, and family name of the font that made the sheets (the first sheet read), one master, *Regular*. The glyphs go in as drawn, with their code points. Its names are set from the sheets' family before its window opens, so the tab is titled after the family (*Hand Regular*; *Untitled Regular* with no family on the sheets).

The list draws each glyph on its baseline, in the window's text color, as every FreeLab list draws glyphs.

## Why FreeLab traces, not FontLab

FontLab 7 has *Element > Image > Autotrace*, evaluated on 171 test images (six fonts' glyphs at 1000, 500, and 300 pixels to the em, clean, sharp-edged, and scan-like): it runs only through its own dialog, one glyph and one History step at a time, it ignores antialiasing, and on ten glyphs its outlines strayed two to four times as far from the drawing as potrace's, with up to eight smooth joins a glyph that bend. FreeLab's tracer follows potrace's published method, written anew from Peter Selinger's paper (potrace itself is GPL), and adds what fonts need: nodes at extremes, outlines turned the font's way, and coordinates in font units.

## The sheet format

A sheet is a whole number of units wide and high (a unit is a square of the corner patterns, about 1/24 of the em). The corners hold finder patterns as QR codes do (7 by 7 units: a black ring, a white ring, a 3 by 3 center), found by their 1:1:3:1:1 runs. Each band holds the layout as compact JSON, compressed, between a 4-byte mark (*FLFB*) and its length, and a CRC-32 after it, one bit a square, the top band read from its top left, the bottom one from its bottom left upward. The reading estimates the sheet's size in units from the corners' distances and each corner pattern's own square size, and tries the sizes near it: only the right one gives the mark and the CRC. From the size, the corners give the map from the sheet to the image (a homography), and each box is taken from the image through it, upright, at the image's own resolution.
