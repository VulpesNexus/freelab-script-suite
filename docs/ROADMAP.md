2. Speed, dark mode's and FontLab's own:
   - *Overlay Fonts* on a large font is FontLab's own slowness: each color change recomputes for about 18 s, on some three cores, with dark mode off (measured on 2026-11-25 with a font of 11,697 glyphs: a press, two moves, and a release on the color field took 19.1, 18.2, 18.0, and 18.4 s in FontLab's handler, and 4 to 6 ms to repaint after). A drag asks for one such recompute per mouse move, so FontLab stops answering. (A quick drag also ran FontLab's stack out, on any font: its color bar lets the event loop run while it handles a move, so moves nested. That one is fixed: FreeLab hands the window one move at a time, see [DARKMODE.md](DARKMODE.md).) Typing the color in the hex or RGB field costs one recompute (12.0 s, against 14.5 s for a click, a press and a release). The cost grows about as the square of the glyph count: one color click took 42 ms on Sarabun (777 glyphs, with its bold overlaid) and 14.5 s on FreeLang Essential (11,697), 345 times longer for 15 times the glyphs, as when each glyph is matched by searching the other font's whole list. "Overlay to layers" costs the same, switching between the two is instant, and FontLab's Python API has nothing for overlays. The cost follows the font of the window the dialog is opened on, not the fonts overlaid: on a 1,374-glyph copy of FreeLang Essential (same family, so *Add Family Members* lists it), a color click took 320 ms with itself overlaid and 344 ms with the two 11,697-glyph styles overlaid too. (The dialog starts with the window's own font overlaid on itself; the earlier figures were each font on itself.) So overlays compare fast when the dialog is opened on a small font holding the glyphs to compare, with the full fonts overlaid on it: *Quick Overlay* makes that font and opens the dialog on it ([QUICK-OVERLAY.md](QUICK-OVERLAY.md); 367 ms a color click with five fonts overlaid, live). Dark mode no longer adds to it: while the mouse is held in a modal dialog, it draws nothing of FontLab's anew until the mouse is let go.
   - Dark mode's own: opening a menu is as fast as in light mode now, and switching tabs about three times slower (230 to 610 ms against 55 to 120: [DARKMODE.md](DARKMODE.md#cost)). What is left: each widget with an effect is drawn offscreen at every repaint, and a changed picture (a scrolled Font window, an edited canvas) is mapped whole, 40 to 60 ms for a canvas; mapping only the rows that changed, with the anchors of the last whole mapping, would cut the second.

## Done

The features the owner asked for, in the owner's order of interest:

1. **Dark mode** for FontLab 7's interface: [DARKMODE.md](DARKMODE.md).
2. Automated kerning: Auto Kerning in Latin, Cyrillic, Greek, kana, Armenian, Georgian, Devanagari, Hebrew, and Thaana, suggested kerning classes, and Kerning Check, [KERNING.md](KERNING.md); Auto Spacing, a sister script, [SPACING.md](SPACING.md).
3. Automated kerning pairs: Auto Kerning measures every pair of a script's letters, figures, and punctuation the font has, and *Common pairs* narrows them to the pairs common in text and kerned in fonts ([KERNING.md](KERNING.md#using-it)).
4. Automated diacritic variants: Glyph Compose, [GLYPH-COMPOSE.md](GLYPH-COMPOSE.md).
5. Automated discretionary and ligature feature code: Feature Code, with alternates that take turns and the features of a font's forms, [FEATURE-CODE.md](FEATURE-CODE.md).
6. A font check (language coverage, vertical metrics, masters): Font Check, [FONT-CHECK.md](FONT-CHECK.md).

What already exists for each, and what FreeLab would build: [FEATURE-SURVEY.md](FEATURE-SURVEY.md).

Reads and writes through an AI app belong to FreeLab MCP, the separate `freelab-mcp` repository, and are on its roadmap.
