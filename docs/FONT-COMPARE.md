# Font Compare

*Scripts > FreeLab > Font Compare* compares two open fonts, or two masters of one font, glyph by glyph: the glyphs only in one, names and code points, advance widths and sidebearings, outlines, components, anchors, kerning, and features. It answers a wish of FontLab's forum (*Font Comparison – A Proposal for FontLab 9*): to see at a glance what changed between two versions of a font, or between two weights of a family. It changes nothing in either font; its only action flags a glyph.

The window keeps the conventions of FreeLab's other dialogs and the look of the redesigned Font Check: a top line with the counts in bold, a settings row, a tab per view, chips that filter a list, a list of glyphs the worst first with small pictures, the selected glyph drawn large, grid lines, a log, a right-click to flag a glyph in FontLab (F3 and Shift+F3 go to the next and previous flagged row), a fresh comparison after an undo, a redo, or an edit in either font, and the dialog's ? button to explain any control. At 1000 by 1000 pixels nothing scrolls sideways.

The header is every window's: the top line (what was compared, or what is missing), then the header's line, shown even before anything can be compared, then the choices, one sentence: *Compare* [font] ⇋ *with* [font] *ignoring differences up to* [1 unit]*.* and the *Compare* button after it. The tabs count in parentheses (*Glyphs (13,956)*, *Kerning (447)*, *Features (26)*), thousands grouped, as the chips do (*Outlines (148)*). Font names are in bold in every line, counts with their nouns in bold, and the names of chips, tabs, and buttons in italics. With no font open, the top line reads, on one line, *No font is open. This window hooks to the next font you open: then choose in with the font to compare it with.*, and *Compare* reads a grayed *n/a* (it stood empty before the swap button: the owner's image 290), which is no font to compare; the window's font, once it comes, takes its place.

The three tabs' rows over their lists (the chips of *Glyphs* and *Kerning*, the tick of *Features*) are as tall as one another, so a list never moves as its tab is shown (the owner's images 285 and 286, seen in Kerning Check): each row stands in a widget of its own, whose least height is the tallest size hint of the controls in any of the rows, the chips hidden until a comparison too, measured as the window is made and again at each switch (`level_rows`).

## Choosing what to compare

Each side is a dropdown. *Compare*, the first, is the window's own font (each FreeLab window belongs to one open font): it lists that font's masters, starting on the one FontLab shows, and with one master it stands as the font's name, in bold, as wide as the name, so the swap button follows it at once (it stood a tab's width away before). *with*, the second, is the free choice, and starts empty (*Choose a font…*, grayed out in the list: it says nothing is chosen yet, and is no choice itself) until one is made, also when exactly two fonts are open: the tool cannot know which font is meant, so the other open font is simply the first row to choose. Its rows: the other fonts open in FontLab, by name, with a row per master for a font with several (*Sans (Bold)*); then the window's own font's masters, only when it has several (a font is compared with itself master against master, never a master with itself); then, under a separator, *Open a font…*; then, under another, the fonts installed on Windows (its *Fonts* folder and the user's own, *%LOCALAPPDATA%\Microsoft\Windows\Fonts*), by their full names, A to Z, those open already left out. Two open fonts of one name are told apart by their files' names (*Sans (Sans-2.vfc)*). The installed fonts' names are read from their files' name tables once a session (again when a folder changes); a file whose name table cannot be read goes by its file's name. The list is read again at each press, focus, and activation of the window, but its rows of installed fonts (some 4,000 on a designer's machine) are made again only when the installed fonts or the open fonts' files change: made and sorted each time, each file compared with each open font's, they took 0.1 s a click with five fonts open.

Picking an installed font opens it in FontLab and chooses it once it is in, as *Open a font…* does with the file picked. *Open a font…* starts its file dialog in Windows' font folder (then where the last font picked came from), opens a font file in FontLab, as *File > Open* does, and chooses it as the second font once FontLab has opened it (looked for twice a second, for up to a minute; a file picked again before then is the one looked for, and while a file picked before it may still come in, only a font with the file's own path is taken); a file already open is chosen at once, and the choice made before stays until then (or for good, when the file dialog is closed without a file).

A font opened either way is compared at once, without a click on *Compare* (the owner asked for it). FontLab makes the new font's window the active one as it lists the font, which sent Font Compare's window behind it and left it there: the window is brought back to the front as the font is chosen, again 0.4 s later, once FontLab has settled, just before the comparison, after it, and 1.5 s after that (FreeLab's tab docking merges a new font window, and makes FontLab's window the active one, once a second). A window minimized or closed meanwhile is left as it is: never restored, and not compared; a click on *Compare* during the 0.4 s compares once. A font closed after a comparison keeps its rows (the lists show the last comparison), but FontLab is asked nothing about it: its glyphs not read yet are drawn empty, and read once it is open again. Closing it moves its History as FontLab reads it, which made the log say *A font's History moved (an undo, a redo, or an edit): compared again* while nothing was compared (the live pass); now the top line and the log say *Libertinus Serif was closed: the comparison is out of date*, once, and the closed font's History is no longer watched. A font picked among those open already is compared at once too (the owner: "Selecting a font that was already loaded in the session should also automatically compare").

The font chosen in *with* (picked, or opened from a file or from the installed fonts) is kept for the rest of the FontLab session, until another is chosen: a *Font Compare* window opened later, or this window once it takes another font, chooses it in *with* and compares with it as it is shown, while it is open (by FontLab's number of the font, else by its file, for a font closed and opened again). It is not chosen at the other readings of the lists (a press on the dropdown), where a comparison would start under the user's pick, nor over a choice or a comparison the window has.

The lists follow the fonts FontLab has open: they are read again when a dropdown is pressed or takes the focus, and when the window becomes the active one. A choice is kept by FontLab's own number of the font (`fgPackage.id`), not by its name, so closing one of two fonts of one name never moves the choice to the other; when the font chosen is closed, the second side is empty again, and the log says so.

*Compare* is grayed until both sides are chosen, and the top line says what is missing: no font open, no second font chosen (with only one single-master font open, it points to *Open a font…*), or the same master on both sides. Nothing is compared as the window opens, but the font kept for the session (above). *Compare* compares again: after a change made elsewhere, or with other differences ignored.

A comparison that takes more than 0.3 s shows the window's progress bar in its top row ([WINDOWS.md](WINDOWS.md)), with its step beside it: reading the first font's glyphs and the second's (4% and 8% of the bar), comparing the glyphs (to 85%, glyph by glyph), the kerning (95%), and the features (98%), then listing the differences. The choices, the swap, the threshold, *Compare*, and the tabs are grayed meanwhile, and the window is redrawn without letting a click or a key through, but the tools menu, the arrows, *Close*, and Esc, which stop it (until the lists start filling): the comparison shown before is put back; the History watchers, dark mode, and the window's release wait too. The glyphs only in one font are no longer read at a comparison: their pictures are read as they are listed (at most 2,000), since a CJK font has thousands that no Latin font has, each read whole before (every node, through FontLab's objects). The arrows between the dropdowns swap two masters of the window's font (and compare again when they had been compared); with another font chosen they are grayed, since the first side stays the window's font: open Font Compare from the other font's window to see that font first.

In sentences and chips, the two sides go by their fonts' names (and their masters' in parentheses when a font has several), by their masters' names when they are two masters of one font, by their files' names when two fonts share a name, and otherwise as *first* and *second*.

*ignoring differences up to [2 units].* (*1 unit* at 1: the box's word follows its number): widths, sidebearings, anchor and component positions, node moves, and kerning values that differ by at most this much count as alike. A font with another number of units per em is scaled to the first one's, and the top line says so.

Comparing a font with itself at another point of its History is out of scope: FontLab's API offers no way to read an earlier state.

## Glyphs

Glyphs are paired by name. A glyph left over in each font with a code point in common is paired too (*uni00E9* and *eacute*), when no other leftover glyph in either font shares that code point (so the pairs are the same whichever font comes first); the pair then differs in its name. The kinds of difference, gravest first:

- **Only in one font**, or, for two masters, **no layer** in one master.
- **Outlines** (the glyph's own contours; components are compared on their own): the number of contours, the number of nodes, how far the node that moved most moved (when both have the same contour and node counts), and how much the shapes differ. The measure of shape is the area where one outline has ink and the other has not (the symmetric difference of the two filled outlines, overlapping contours counted once and counters left empty, as FontLab fills them), as a share of the larger outline's ink: 0% for the same shape, 100% where one has no ink, and up to 200% for two shapes that do not overlap at all (a mark moved away). A shape counts as changed past 0.2% of its ink, about what a node moved by 10 units on a 700-unit letter changes. When the nodes moved but the shape did not, and the nodes are the same in another order, the sentence says so (*the same nodes in another order (start points or contour order)*).
- **Components**: those only in one font (the second font's component names translated through the glyph pairs above), one used more times in one font than in the other (a colon of two dots against one), the same ones in another order, one moved (by its offset), and one scaled or turned.
- **Names and code points**: a glyph paired by its code point, and code points that differ.
- **Metrics**: the advance width, and the left and right sidebearings (the ink measured with components, as FontLab draws the glyph). A glyph with no ink compares its width only.
- **Anchors**: those only in one font, and those moved.

The view has three parts.

- **Chips**, at the top: one per kind with the number of glyphs that have it in parentheses (*Only in Sans (3)*, *Outlines (40)*, *Metrics (12)*), all shown to start but the two of the glyphs only in one font, so that the list compares what both fonts have (the owner: they "should probably be unchecked by default so it truly focuses on comparing what is available in both fonts"); when nothing both fonts have differs, those two are shown instead. A chip shows or hides its kind of difference in the list: hidden, that kind leaves every row's short differences and the ranking, and a glyph left with no kind shown leaves the list; the line above the list says it all on one line, with the kinds hidden (*632 glyphs differ (231 shown; hidden: Only in A, Only in B).*; the owner: "Those two short lines can be on one line only"). (Hiding only the glyphs that had nothing else hid nothing for *Metrics*: an outline or component change moves the sidebearings too, so nearly every glyph whose metrics differ differs otherwise as well.) A chip shown is filled in the highlight color, a chip hidden is a gray outline, drawn from the palette in light and dark mode alike.
- **The glyphs that differ**, at the left, the worst first: by the gravest kind each has, then by how much (the share of the shapes, the largest metric change), then by name. Each row has a small picture of the glyph from both fonts, the first in the text color and the second in the highlight color, see-through, its name (both names when they differ), and its differences in short (*outline 4.1%; width +20*). The tooltip has the whole sentence. At most 2,000 glyphs are listed, the worst; two weights of one family differ in nearly every glyph, and the chips narrow the list. A right-click flags the glyph in the first font.

There is no *Show in Glyph window* here (nor a double-click for it): FontLab opens a Glyph window on its current font only (FreeLab opens one through FontLab's *New Glyph Tab* command and `flItems.requestContent`, neither of which takes a font), so a glyph of the other font, or of a font that is not the current one, would show in the wrong font. Open the glyph from its own font's Font window.
- **The comparison**, at the right: the selected glyph at one scale in three panels, the first font's in the text color, both overlaid, and the second font's in the highlight color, with the baseline and each advance width drawn thin and dashed; a font without the glyph shows a dashed empty frame. A color glyph (shapes with colors of their own, as FontLab imports a COLR font) is drawn in its own colors in its own panel, at the second font's scale in the second panel; the overlay keeps the two comparison colors. Under it, its differences in one sentence: *a, Regular and Bold: the shapes differ by 4.1% of the ink; nodes moved up to 12 units (contour 2); width 520 and 540 (+20).*

## Kerning

Each master's kerning is read as FontLab applies it: `getPlainPairsDict()` resolves class kerning to glyph pairs (Auto Kerning's `FontKerning`). Where it is missing, the entries are resolved here the same way: the most specific entry wins, glyph and glyph, then glyph and class, then class and glyph, then class and class. Values are compared as applied, so a pair kerned 0 and a pair not kerned are alike, and a pair kerned by a class in one font and by its own entry in the other is alike when the values are.

Chips: *Only in* one font, the other font, *Differing values* (the pairs both fonts kern, with values that differ; *Other values* before), and *Glyphs one font lacks* (pairs of a glyph that one font does not have: they follow from the glyphs that differ). Only *Differing values* is shown to start with (the owner: "it should default to 'Differing values' … only different to ticking everything else if there's nothing falling under that category"); when no pair has differing values, every other kind is shown but *Glyphs one font lacks*, which is shown only when it is all there is (owner's image 369), and *Differing values* stays in the row, grayed, as *Differing values (none)*. The list has the pair, its value in each font, and the second's minus the first's, the largest difference first; at most 2,000 pairs are listed. The selected pair is drawn in both fonts, each at its own value, one over the other: the same two characters in each (the second font's glyphs found by the first's names, through the glyphs paired by code point), each font drawn at the same size whatever its em, each caption giving the value in the first font's units.

A value that looks wrong may be the font's own. The owner's image 294 showed BIZ UDGothic's *øM: 0* over *!The Black Bloc: -1392*, the second pair's glyphs piled onto each other. The font kerns that pair so: its regular style (1,024 units per em) has *oslash M* at -696 in its `kern` table (format 0, 447 pairs) and in its GPOS `kern` feature (lookup 0, PairPos format 1, the same 447 pairs, no classes), as it has *oslash L*; read with fontTools on 2026-11-18. BIZ UDGothic has 2,048 units per em, so the second font's values are scaled by 2 (the top line says so): -696 is -1392 in the first font's units, drawn as -696 in its own em. -696 is more than the ø's whole advance (546), so the M starts left of the ø.

## Features

The features are read from each font's feature code (`fgPackage.features`): the code before the features (*Prefix*), each feature, and the classes of FontLab's *Classes* panel (*Classes*, as code: `@name = [glyphs];`). Line ends, spaces at the ends of lines, and blank lines at the start and end are ignored. The list shows the features only in one font and those whose code differs (*2 lines only in Regular, 1 line only in Bold*); *Show the features that are alike* lists the others too. Its caption counts them once two fonts are compared (*Show the 31 features that are alike*, *Show the feature that is alike*), and it is grayed, its tooltip saying why, when no feature is alike: two fonts of different families often have none (every feature differs or is only in one), so the tick had nothing to add, and the owner saw no change on ticking it (image 293). The selected feature's code is shown with the lines only in the first font on a red tint, after a minus, the lines only in the second on a green tint, after a plus, three unchanged lines around each change, and the rest left out (an ellipsis). The code is written in the view's colors as they are when it is usable: a font compared from this tab was shown dimmed until another feature was selected, since the view is grayed while comparing and its colors were read then (the owner's image 233). FontLab writes the code it generates between `#> feature` and `#< feature`; that code is compared as any other.

Two masters of one font share their features and classes: the tab says so.

## What it does not compare

Font info (names, vertical metrics, and the rest), guides, hints, node smoothness, glyph flags, notes, and tags are not compared. Outlines are compared as drawn, not as they interpolate: Font Check's *Masters* view does that. A TrueType contour's two off-curve points in a row are read as a cubic curve, since FontLab's nodes say only *on* and *off*; both sides are read the same way, so the shape measure still compares like with like (on three corpus fonts read both ways, the same glyphs differed, and a glyph's measure moved by at most 8.4 percentage points).

## How it was checked

The comparisons (pairing glyphs, the shape measure, outlines, metrics, components, anchors, code points, the ranking, kerning resolved and compared, features compared line by line, and the colored code) sit above the Qt line and are unit tested under Python 3 and 2.7 (*tests/compare_tests.py*): areas are exact for straight edges (a corner moved 10 units on a square of 100 gives the 500 units of its triangle), counters and overlaps are filled as FontLab fills them, and a circle of four curves comes within 1% of π·r². The dialog is run on fakes of PythonQt and of FontLab fonts (two fonts with planted differences, and a font of two masters), which exercises its code paths but not Qt's or FontLab's answers. The two dropdowns are fakes too (rows, a separator as a row, the current row, and the two signals): what the real ones do is listed below.

On corpus fonts read with fontTools (open-licensed, checked as *kerning/train/dataset.py* checks them), with variable fonts instanced at their weight axis's ends:

- **EB Garamond** (3,247 glyphs, 400 and 800): 3,230 glyphs differ (outlines 1,216, components 1,304, metrics 3,200), compared in 2.0 s under Python 3 and 2.0 s under Python 2.7; its 31 features alike.
- **Noto Sans** (4,515 glyphs, 100 and 900): 4,253 differ (outlines 2,418), 2.4 s under Python 3 and 2.2 s under Python 2.7; its 36 features alike.
- **Cairo** (1,956 glyphs, 200 and 1000): 1,954 differ, 0.6 s.
- Each font against itself: no difference.
- Each font against a copy with six changes planted (a node moved by 10 units, an advance width by 12, a glyph removed, a glyph renamed, a contour's start point or the contours' order changed, a component moved by 15 units), two kerning changes, and two feature changes: every change found, and nothing else.

The pictures (the three-panel comparison, the small pictures, the colored code) were drawn offscreen under PySide6 (Qt 6), PythonQt's ways emulated, in light and dark palettes, and looked at; that harness is not in the repository. Reading glyphs through FontLab's objects adds its own time, as in Font Check's *Masters* view.

## FontLab calls not yet proven live

Proven before (see FreeLab MCP's *FONTLAB7-API.md* and Font Check's notes): `flWorkspace.instance().packages()` and `fontlab.flPackage(item)` for the open fonts, the current font, `fgPackage.glyphs` (`name`, `unicode`, `unicodes`), `findName`, `getLayerByName`, a layer's `shapes`, a shape's `contours` and `isComponent`, a contour's `nodes()` (a node's `x`, `y`, and `type`: *on* or *off*), `advanceWidth`, `masters`, `master`, `upm`, `tfn`, `kerning(master)` and `getPlainPairsDict()`, `fgPackage.features` (`keys()`, `get_feature`, `get_prefix`), the History state, and flags. To look at live: a component's `shape.transform` as its offset and scale (Font Check reads a shape's transform for its contours only), `shape.shapeData.componentGlyph` (Font Check uses it), a layer's `anchors` and an anchor's `point` (Glyph Compose reads them), `package.getAllGroups()` for the Classes panel's classes (documented, its feature classes with `kernGroup` false), that raising the window and `activateWindow` from a timer brings it back over the font window FontLab activates as it opens a font (0.4 s may be too soon for a large font: the raise after the comparison is the fallback), `QEventLoop.ExcludeUserInputEvents` in the comparison's redraws (CJK Vertical uses it already), `flItems.requestLoadingFont(path)` for *Open a font…* (and whether a font opened from a binary file, such as an OpenType one, gives that file as its `path`: otherwise an open file picked again is looked for as a new one, and not found), and how long FontLab takes to hand over every node of two large fonts. Qt calls no FreeLab dialog used before, each guarded or plain Qt: `QComboBox.setSizeAdjustPolicy(AdjustToMinimumContentsLengthWithIcon)` and `setMinimumContentsLength`, `QComboBox.insertSeparator` (its row counted among the dropdown's rows, as the code assumes), the `activated(int)` signal (sent for a row the user picks, also with the keyboard or the wheel, and not for the code's own `setCurrentIndex`), an event filter on the dialog and on both dropdowns that reads the open fonts again on a mouse press, a focus-in, and a window activation (event types 2, 8, and 24), refilling a dropdown inside that filter just before its list opens, `fgPackage.id` as stable and distinct for every open font, `QSpinBox.setSuffix` set again from `valueChanged(int)`, `QTabBar.setTabText`, `QTransform.scale` and `map` on a `QPainterPath`, rich text with a table and `pre` in a `QTextEdit`, and a stylesheet on each chip (`QToolButton` with `:checked` and `:hover`, and `palette(highlight)`, `palette(highlighted-text)`, and `palette(window-text)`).
